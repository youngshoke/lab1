## ответы на контрольные вопросы (раздел 7)

1. **lambda vs def.** `lambda` — анонимная функция из одного выражения
   без имени и без `return` (значение выражения возвращается неявно);
   `def` создаёт именованную функцию, тело которой может содержать
   произвольное число операторов, циклы, несколько `return` и docstring.
   Ограничение lambda: нельзя разместить внутри операторы (`if` как
   оператор, циклы, присваивания) — только одно выражение.

2. **map().** Возвращает не список, а ленивый итератор (объект `map`);
   элементы вычисляются по требованию. Чтобы получить список, нужно
   явно обернуть в `list(map(...))`.

3. **filter().** Оставляет из итерируемого объекта только те элементы,
   для которых функция-предикат возвращает истинное значение. Если
   предикат всегда возвращает `False`, результатом будет пустой
   итератор (после `list()` — пустой список `[]`).

4. **Порядок reduce().** Для списка `[a, b, c, d]` и `initializer=x`:
   сначала `func(x, a)` → `r1`, затем `func(r1, b)` → `r2`, затем
   `func(r2, c)` → `r3`, затем `func(r3, d)` → итоговый результат.
   Каждый шаг «сворачивает» накопленное значение с очередным элементом.

5. **List comprehension vs generator expression.** Comprehension
   (`[... for ... ]`) сразу строит список в памяти; generator
   expression (`(... for ...)`) создаёт ленивый генератор, элементы
   которого вычисляются по одному при итерации. Генератор
   предпочтителен, когда данные большие/бесконечные или нужен только
   однократный проход — экономит память.

6. **Функция высшего порядка.** Функция, принимающая другую функцию как
   аргумент и/или возвращающая функцию как результат. Пример из работы:
   `apply_to_all(func, items)` из задания 6 принимает `func` и применяет
   её к каждому элементу.

7. **Части рекурсивной функции.** Базовый случай (условие остановки,
   возвращающее результат без дальнейшего вызова) и рекурсивный случай
   (вызов функции с более простым/меньшим аргументом). Без базового
   случая рекурсия никогда не остановится и приведёт к `RecursionError`;
   без рекурсивного случая функция не сможет решить исходную задачу —
   это будет просто обычная функция без рекурсии.

8. **RecursionError в CPython.** CPython ограничивает глубину стека
   вызовов (по умолчанию около 1000), так как каждый вызов функции
   занимает кадр стека, а сам стек интерпретатора конечен. Предотвратить
   можно: переписать алгоритм итеративно (циклом), использовать
   хвостовую оптимизацию вручную через накопитель + `while`, увеличить
   лимит через `sys.setrecursionlimit()` (рискованно — может привести к
   переполнению системного стека), либо ограничить глубину входных
   данных.

9. **reduce() vs цикл с накоплением.** По сути `reduce()` делает то же
   самое, что цикл `for x in iterable: acc = func(acc, x)`, но в
   функциональном стиле: без явного изменяемого счётчика/переменной в
   теле алгоритма пользователя, в виде одного выражения, что облегчает
   компоновку в конвейеры (`filter` → `map` → `reduce`) и делает код
   декларативным, а не императивным.

10. **Что можно переписать через comprehensions.** Задания 2, 3
    (map/filter) уже переписаны в задании 4 через comprehension — это
    прямая замена, так как оба используют одну функцию к каждому
    элементу/предикат без побочных эффектов. Задание 8 частично можно
    переписать как `sum(e["salary"] for e in employees if ...)`
    (generator expression вместо filter+map+reduce), но чистая свёртка
    через `reduce()` в общем случае удобнее там, где операция свёртки
    не сводится к `sum`/`any`/`all` (например, нужен кастомный
    аккумулятор, как в `factorial_reduce` или `max_reduce` из задания 5)
    — там comprehension не заменит `reduce()` напрямую.
